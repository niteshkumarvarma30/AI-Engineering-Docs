# Lesson 10.1 - Temperature: Sharper vs Flatter

## 1. What is Temperature?

In LLM text generation, temperature controls how concentrated or spread out the next-token probability distribution is.

Temperature is normally written as `T`.

```text
P(i) = exp(z_i / T) / sum_j exp(z_j / T)
```

where:

- `z_i` = logit of token `i`
- `T` = temperature
- `P(i)` = probability of token `i`

The main rule is:

```text
Lower T  -> sharper distribution
Higher T -> flatter distribution
```

---

## 2. What Does "Sharper" Mean?

Suppose an LLM predicts:

```text
A -> 70%
B -> 25%
C -> 5%
```

Most probability is concentrated on `A`.

This is a **sharper distribution**.

```text
A: ██████████████████████████████
B: ██████████
C: ██
```

So:

```text
Sharper = probability is concentrated on fewer tokens
```

A sharper distribution usually makes generation more predictable.

---

## 3. What Does "Flatter" Mean?

Suppose the distribution is:

```text
A -> 45%
B -> 35%
C -> 20%
```

The probability is more evenly spread.

This is a **flatter distribution**.

```text
A: ██████████████████
B: ██████████████
C: ████████
```

So:

```text
Flatter = probability is spread across more tokens
```

A flatter distribution usually allows more diversity when sampling.

---

## 4. Why Does Temperature Do This?

Temperature changes the logits before softmax:

```text
P(i) = softmax(z_i / T)
```

### Low temperature

Suppose:

```text
Original logits:

[5, 4, 1]
```

With:

```text
T = 0.5
```

we get:

```text
[5/0.5, 4/0.5, 1/0.5]

= [10, 8, 2]
```

The differences between logits become larger.

Therefore softmax becomes more concentrated:

```text
T < 1 -> larger effective logit differences -> sharper
```

### High temperature

With:

```text
T = 2
```

we get:

```text
[5/2, 4/2, 1/2]

= [2.5, 2, 0.5]
```

The differences become smaller.

Therefore softmax becomes more spread out:

```text
T > 1 -> smaller effective logit differences -> flatter
```

---

## 5. Numerical Example

Suppose the model produces:

```text
Token A -> 5
Token B -> 4
Token C -> 1
```

### T = 1

Approximately:

```text
A -> 72.7%
B -> 26.8%
C -> 0.5%
```

This is relatively concentrated.

### T = 0.5

Scaled logits:

```text
[10, 8, 2]
```

Approximately:

```text
A -> 88.1%
B -> 11.9%
C -> 0.0%
```

Much sharper.

### T = 2

Scaled logits:

```text
[2.5, 2, 0.5]
```

Approximately:

```text
A -> 54.7%
B -> 33.1%
C -> 12.2%
```

Much flatter.

### Compare

| Temperature | A | B | C | Shape |
|---|---:|---:|---:|---|
| `T = 0.5` | 88.1% | 11.9% | ~0% | Sharper |
| `T = 1.0` | 72.7% | 26.8% | 0.5% | Normal |
| `T = 2.0` | 54.7% | 33.1% | 12.2% | Flatter |

The pattern is:

```text
T decreases
-> logit differences become larger
-> probability concentrates
-> SHARPER
```

and:

```text
T increases
-> logit differences become smaller
-> probability spreads
-> FLATTER
```

---

## 6. Easy Mental Model

Remember:

```text
LOW temperature
      |
      v
Focus on top choices
      |
      v
SHARPER
      |
      v

```

```text
HIGH temperature
      |
      v

      |
      v
FLATTER

```

This is an intuition for decoding, not a claim that the model literally "thinks harder" or "thinks less".

---

## 7. Restaurant Analogy

Imagine the model is choosing a restaurant.

Initial preferences:

```text
A -> 70%
B -> 20%
C -> 10%
```

With lower temperature, the distribution may become more concentrated:

```text
A -> 90%
B -> 9%
C -> 1%
```

The model almost always chooses A.

That is **sharp**.

With higher temperature, it may become:

```text
A -> 50%
B -> 30%
C -> 20%
```

Now alternatives have more probability.

That is **flat**.

---

## 8. Does Temperature Change the Ranking?

For positive temperature values, temperature does not change the ranking.

Original:

```text
A = 5
B = 4
C = 1

A > B > C
```

At `T = 0.5`:

```text
10 > 8 > 2
```

Still:

```text
A > B > C
```

At `T = 2`:

```text
2.5 > 2 > 0.5
```

Still:

```text
A > B > C
```

So:

```text
Temperature changes probability gaps.
Temperature does not change ranking for T > 0.
```

---

## 9. What About T = 0?

Mathematically, `z / T` is undefined at exactly zero.

In practical LLM APIs, `temperature = 0` is handled as a special case or approximates greedy decoding.

The practical intuition is:

```text
T -> 0
-> distribution becomes extremely concentrated
-> highest-logit token dominates
```

Exact reproducibility can still depend on the model, serving system, numerical behavior, and other decoding settings.

---

## 10. Temperature and Sampling

Temperature matters especially when the model **samples** from the probability distribution.

Suppose:

```text
A -> 60%
B -> 25%
C -> 10%
D -> 5%
```

Sampling means the model does not necessarily choose A every time.

For example:

```text
Run 1 -> A
Run 2 -> A
Run 3 -> B
Run 4 -> A
Run 5 -> C
```

Lower temperature makes the distribution more concentrated.

Higher temperature makes it flatter.

Therefore:

```text
Low T
-> less diversity
-> more predictable
-> more focused
```

```text
High T
-> more diversity
-> less predictable
-> more exploratory
```

---

## 11. Temperature Does Not Create New Information

Temperature does not add new tokens or new knowledge.

If the model has:

```text
A -> 5
B -> 4
C -> 1
```

temperature only changes how probability is distributed among these candidates.

So:

```text
Temperature = probability reshaping
```

not:

```text
Temperature = new knowledge
```

---

# 12. Temperature vs Top-k

Do not confuse temperature with `top-k`.

They work differently.

### Temperature

```text
Temperature
    |
    v
Reshape probabilities
```

### Top-k

```text
Top-k
    |
    v
Remove low-ranked candidates
```

Suppose:

```text
A -> 50%
B -> 25%
C -> 10%
D -> 8%
E -> 7%
```

If:

```text
k = 2
```

keep:

```text
A, B
```

Then renormalize:

```text
A = 50 / (50 + 25)
  = 66.7%

B = 25 / (50 + 25)
  = 33.3%
```

So top-k changes the **candidate set**, while temperature changes the **shape of the probability distribution**.

A useful memory trick:

```text
Temperature = SHAPE
Top-k       = CUT
```

---

## 13. Effect of Different Top-k Values

Starting distribution:

```text
A -> 50%
B -> 25%
C -> 10%
D -> 8%
E -> 7%
```

### top-k = 1

Keep only:

```text
A
```

After renormalization:

```text
A -> 100%
```

This is effectively greedy selection.

### top-k = 2

Keep:

```text
A, B
```

After renormalization:

```text
A -> 66.7%
B -> 33.3%
```

### top-k = 3

Keep:

```text
A, B, C
```

After renormalization:

```text
A -> 58.8%
B -> 29.4%
C -> 11.8%
```

Therefore:

```text
Smaller k -> fewer candidates -> more restrictive
Larger k  -> more candidates -> more diversity
```

---

## 14. Temperature vs Top-k

| Feature | Temperature | Top-k |
|---|---|---|
| Main job | Reshape probabilities | Limit candidates |
| Removes tokens? | No | Yes |
| Low value | Sharper | Fewer candidates |
| High value | Flatter | More candidates |
| Controls diversity | Yes | Yes |
| Main mechanism | Scale logits | Truncate candidate set |

Remember:

```text
Temperature -> SHAPE
Top-k       -> CUT
```

---

## 15. Temperature vs Top-p

Top-p is another sampling strategy.

Instead of keeping exactly `k` tokens, top-p keeps the smallest set of highest-probability tokens whose cumulative probability reaches `p`.

Example:

```text
A -> 0.50
B -> 0.25
C -> 0.10
D -> 0.08
E -> 0.07
```

Suppose:

```text
top-p = 0.85
```

Cumulative probability:

```text
A                  = 0.50
A + B              = 0.75
A + B + C          = 0.85
```

So the candidate set becomes:

```text
A, B, C
```

Top-p dynamically changes the number of candidates.

---

## 16. The Three Controls

Think of them like this:

```text
Temperature
    |
    v
Changes probability SHAPE
```

```text
Top-k
    |
    v
Keeps exactly K candidates
```

```text
Top-p
    |
    v
Keeps enough candidates to reach cumulative probability P
```

Therefore:

```text
Temperature -> shape
Top-k       -> fixed-size cutoff
Top-p       -> probability-based cutoff
```

## 17. Complete Generation Pipeline

An LLM generation process can be viewed as:

```text
Input tokens
     |
     v
Transformer
     |
     v
Hidden state
     |
     v
LM Head
     |
     v
Logits
     |
     v
Temperature scaling
     |
     v
Softmax
     |
     v
Probability distribution
     |
     +------> Top-k / Top-p filtering
     |
     v
Sampling
     |
     v
Selected next token
     |
     v
Append token to sequence
     |
     v
Repeat
```

Exact ordering of temperature and filtering can vary by implementation, but their conceptual roles remain different.

## 18. Why Low Temperature Feels More Deterministic

Suppose:

```text
A -> 90%
B -> 7%
C -> 3%
```

Even with sampling enabled, A is overwhelmingly likely.

But if:

```text
A -> 40%
B -> 35%
C -> 25%
```

several choices have substantial probability.

So:

```text
Low T -> focused / predictable
High T -> diverse / variable
```

---

## 19. Temperature Is a Decoding Parameter

A common misunderstanding is:

```text
High temperature = smarter
Low temperature = less intelligent
```

That is incorrect.

Temperature is a **decoding parameter**.

It changes how the trained model's output distribution is used.

It does not:

- retrain the model
- add knowledge
- increase parameter count
- increase the underlying reasoning ability

---

## 20. Connection to Logits

From the previous lesson:

```text
Hidden state
    |
    v
LM Head
    |
    v
Logits
```

For example:

```text
z = [5, 4, 1]
```

Temperature modifies them:

```text
z' = z / T
```

Then softmax converts them to probabilities:

```text
P = softmax(z')
```

Complete relationship:

```text
Transformer
    |
    v
Hidden state
    |
    v
LM Head
    |
    v
Logits
    |
    v
Temperature
    |
    v
Softmax
    |
    v
Probabilities
```

```text
-> SHARPER

```

```text
HIGH temperature
-> smaller effective logit differences

```


